# CLI-Anything Fizzy Harness — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install CLI-Anything as a shared Baum workspace tool and generate a CLI harness for Fizzy, enabling programmatic and agent access to the Kanban board at tasks.baum.to.

**Architecture:** CLI-Anything is already installed as a Claude Code plugin. We also clone the repo to `~/Baum/tools/cli-anything/` as a shared reference. We invoke the plugin's `/cli-anything` command against the Fizzy source to auto-generate a harness. Post-generation, we add a connection layer so the harness can reach the Fizzy instance running on mini1. The harness is installed system-wide as `cli-anything-fizzy`.

**Tech Stack:** Python 3.10+, Click 8.0+, Ruby on Rails (Fizzy), Docker (mini1), SSH

**Spec:** `docs/superpowers/specs/2026-04-09-cli-anything-fizzy-harness-design.md`

### Task 3: Add Connection Layer to mini1

**Files:**
- Create: `~/.config/cli-anything-fizzy/config.json`
- Modify: Files in `/Volumes/2TB/Baum Products/fizzy/agent-harness/cli_anything/fizzy/` (specific files depend on what was generated in Task 2)

This task adapts the generated harness to talk to the live Fizzy instance on mini1. The exact approach depends on what CLI-Anything generated.

- [ ] **Step 1: Evaluate the generated connection approach**

Read the main CLI file and core modules:

```bash
cat "/Volumes/2TB/Baum Products/fizzy/agent-harness/cli_anything/fizzy/fizzy_cli.py"
ls "/Volumes/2TB/Baum Products/fizzy/agent-harness/cli_anything/fizzy/core/"
```

Determine which category the generated code falls into:

- **A) Rails console commands** — Look for `rails runner`, `rails console`, or Ruby code execution patterns
- **B) HTTP/API calls** — Look for `requests`, `urllib`, HTTP endpoints, URL configuration
- **C) Direct database** — Look for SQLite connections, SQL queries, direct file path references
- **D) File-based** — Look for file path operations on `.xml`, `.json`, or similar (unlikely for a web app)

- [ ] **Step 2: Create connection config**

```bash
mkdir -p ~/.config/cli-anything-fizzy
```

Write `~/.config/cli-anything-fizzy/config.json`:

```json
{
  "fizzy_host": "mini1",
  "fizzy_url": "https://tasks.baum.to",
  "fizzy_container": "fizzy",
  "connection_mode": "<determined-from-step-1>",
  "docker_exec_prefix": "ssh mini1 \"export PATH=/opt/homebrew/bin:$PATH && docker exec fizzy\"",
  "rails_runner_prefix": "ssh mini1 \"export PATH=/opt/homebrew/bin:$PATH && docker exec fizzy bin/rails runner\""
}
```

- [ ] **Step 3: Modify the harness to use the connection layer**

This step is adaptive. Based on what was generated:

**If Rails console (A):** Wrap Ruby execution calls to route through SSH + Docker:
- Find where the harness executes Ruby/Rails commands
- Replace local execution with: `subprocess.run(["ssh", "mini1", f"export PATH=/opt/homebrew/bin:$PATH && docker exec fizzy bin/rails runner '{ruby_code}'"])`

**If HTTP (B):** Point the base URL to `https://tasks.baum.to`:
- Find URL configuration in the harness
- Set base URL to `https://tasks.baum.to`
- Add access token auth header if the harness supports it

**If Direct DB (C):** Set up SSH tunnel:
- Create a helper that runs `ssh -L 3007:localhost:3006 mini1` for tunnelling
- Point DB connection to the tunnelled port

**If File-based (D):** This is unlikely for a web app. If it happened, the harness needs significant rework — skip to Task 4 notes.

- [ ] **Step 4: Test a basic command against live Fizzy**

```bash

```

Expected: JSON output listing boards from the live Fizzy instance on mini1. If this fails, check:
- SSH connectivity: `ssh mini1 "echo ok"`
- Docker: `ssh mini1 "export PATH=/opt/homebrew/bin:\$PATH && docker ps --filter name=fizzy"`
- Rails runner: `ssh mini1 "export PATH=/opt/homebrew/bin:\$PATH && docker exec fizzy bin/rails runner 'puts Board.count'"`
